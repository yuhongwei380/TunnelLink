# 步骤三 连接集成与发行验收

状态：核心代码与自动化测试已实施。Windows 代码检查、前端构建及自动化通过；当前工作区缺少随包引擎和驱动，尚未完成安装包、实际 VPN 与 macOS 联调。以下验收矩阵是发布前要求，不表示所有真实环境测试已经完成。依赖[步骤一 构建能力与配置模型](multi-profile-step-1.md)和[步骤二 配置与证书导入](multi-profile-step-2.md)。

本步骤让选中的配置贯穿连接、认证、日志和界面，并完成三种发行方式的验证。不得把“添加配置成功”作为整个需求完成的标志。

## 先验证引擎认证能力

现有 `vpn.rs` 和 `worker.rs` 均要求用户名、密码非空，监督进程固定传递 `-u/-p` 并读取编译内置配置。实施时先用仓库锁定版本的引擎验证：账号密码、仅证书、证书加账号密码三种认证方式，以及未提供凭据时的行为。

仅证书认证必须允许省略 `-u/-p`，不能填入占位账号。配置解析结果可以决定是否显示登录框，但服务端挑战或不支持的认证方式应返回明确错误，不能错误地判为普通密码失败反复重试。若锁定引擎需要修改才能支持某项范围，应先补充引擎改动与验证，再对该项宣称支持。

## 连接状态与配置绑定

`ConnectOptions` 新增 `profileId`，账号密码字段按认证类型使用。后端重新检查编译能力、配置存在性和认证要求，不能只信任前端当前选择。

发起连接时，在同一临界区取得配置、revision、凭据命名空间和运行策略，生成不可变会话快照。连接建立前后均绑定同一个 profileId/revision。UI 列表变化不能改变进行中的会话。

保留现有单会话控制与 generation 机制。选择切换、活动配置删除和连接启动使用一致的锁顺序；断开请求后必须等待监督进程退出及资源清理完成，才能切换配置。导入新配置可在会话期间完成，但不能自动选中。

状态返回新增 `activeProfileId` 和 `activeProfileRevision`；选择项与活动项分别维护。配置 A 的延迟事件不得覆盖配置 B 的状态、错误或保存凭据。没有可用选择时禁止连接，不回退到另一个环境发起连接。

## 监督进程改造

1. 普通进程将规范化配置写入当前私有会话目录的固定文件名，例如 `profile.ovpn`。请求中只记录配置指纹等必要信息，不接受用户指定的引擎路径、shell 命令或任意文件路径。
2. 监督进程通过受约束的会话文件读取函数读取，校验文件类型、权限、大小及内容策略，并对比指纹。指纹用于一致性检查，不能代替授权和内容校验。
3. 校验与执行使用同一份读取到的字节，将其写入监督进程自行创建的私有临时文件，再传给固定的引擎。避免校验后重新打开可被替换的源路径。
4. 根据认证方式传递凭据；保留现有引擎启动后的凭据文件删除机制。会话配置、引擎原始日志和临时文件在会话结束后清理，异常退出也纳入恢复处理。
5. 继续沿用 Windows 作业对象/隐藏控制台和 macOS 提权机制，验证重连、统计采集、取消和停止未退化。

Windows 的会话读取路径也要检查重解析点和访问权限；不能只依赖当前普通 `OpenOptions` 行为。用户可导入的配置不得成为高权限任意文件读取或脚本执行入口。

## 每配置凭据

`credentials.rs` 从全局 `vpn-account` 改为按应用标识、profileId 和 revision 区分条目，密码仍进入系统凭据库，不放入元数据文件。内置配置内容更新也应使旧凭据失效。

前端 `useVpnConnection.ts` 的 sessionCredentials、attemptedCredentials 和异步加载结果均绑定配置身份。切换时清空表单密码与旧认证错误，随后加载目标配置的凭据；过期异步响应直接丢弃。

只在对应配置成功连接且用户选择记住后保存凭据。删除、取消、切换和卸载应阻止滞后的保存任务复活旧条目。维护可枚举的凭据条目标识记录，以便删除配置和卸载时完整清理；记录中不保存秘密。

## 界面与地址展示

保留现有连接页布局和视觉风格，添加配置选择器和管理弹窗；不用截图中的 OpenVPN Connect UI。

- 显示配置名称、说明、来源及服务器候选域名/IP、端口。内置名称与说明由编译设置提供，名称缺省 `Internal Tunnel`；不硬编码 Demo 标签。
- 用户导入配置只标记为导入，不根据文件名猜测是生产、内部或测试环境。
- 已连接时清晰显示活动配置。原有分配 IP、隧道网关、流量统计继续保留；若展示实际远端地址，须来自引擎可验证的会话事件，与配置候选地址分开。
- 关闭导入时不显示添加入口，且后端拒绝历史导入项连接。内置关闭且无导入配置时显示导入引导。
- 重命名、删除和错误提示支持现有中英文；文件名与说明按文本渲染。

域名和 IP 按用户要求真实展示，包括配置列表、连接状态和诊断输出。现有 `log-privacy.json` 的 endpointAlias 不应继续替换本方案中的地址；构建时若发现非空旧别名，给出明确迁移错误并提示移除，不静默继承。密码、私钥等敏感材料继续脱敏，地址展示与秘密保护采用独立规则。

## 自动化与真实环境验收

按改动运行现有 `npm run test:unified`、`npm run test:ui`、`npm run test:native`，补充覆盖配置策略、导入失败、身份隔离和构建组合的测试。完成后运行 `npm run check` 与 `npm run check:native`；使用实际平台工具链执行相关打包验证。

| 场景                                | 预期                                         |
| ----------------------------------- | -------------------------------------------- |
| 外部体验版全新安装                  | 只有内置配置，名称来自编译配置，无导入能力   |
| 内部通用版全新安装                  | 内置与多个导入项共存，可分别连接             |
| 纯导入版全新安装                    | 不包含内置材料，首次导入后可连接             |
| 从通用版升级为体验版                | 历史导入项不可使用，数据不自动删除           |
| 内置配置变更或关闭                  | 旧凭据不复用，不自动切换并连接其他环境       |
| 两个不同服务器配置                  | 分别核实实际远端、路由/DNS 和凭据，不串用    |
| 外部 CA 和 cert/key                 | 导入后移走源文件仍可连接，验证失败有明确提示 |
| 连续切换与取消连接                  | 旧事件不污染新会话，断开清理后才能切换       |
| 错误 CA、账号密码错误、服务器不可达 | 错误类型可区分，不自动回退内置配置           |
| 删除与卸载                          | 私钥副本和凭据被清理，失败可见且可重试       |
| 真实地址展示                        | 域名、IPv4、IPv6 不被别名替换，秘密不泄露    |

Windows 和 macOS 均需至少完成内置连接、两份导入配置切换、断开、重启恢复、权限和卸载验证。真实连接验收需要可用的 Demo 与内部测试 VPN、对应账号及证书；自动化通过不能替代这些结果。

## 交付边界

三个步骤可拆成三个顺序实现的变更，但对外发布应等待全链路通过。实现时同步更新构建、开发、自定义配置说明和发行记录。所有测试使用专用假材料或隔离环境，不将内部配置、证书私钥或账号提交到仓库。

暂不包含多隧道并发、配置云同步、自动订阅更新、MFA、加密私钥解锁和证书独立资产管理。遇到此类配置应说明不支持的具体能力，而不是保存为可连接状态。
