# 步骤二 配置与证书导入

状态：核心代码已实施，真实引擎导入与双平台连接仍待联调。实施调整：导入采用一次原生交互，不暴露前端草稿接口；所有外部材料均由用户通过选择器明确选择，适配 Windows GUI 当前整体提权的权限边界；取消时不持久化材料。以下保留设计分解。依赖[步骤一 构建能力与配置模型](multi-profile-step-1.md)；完成后进入[步骤三 连接集成与验收](multi-profile-step-3.md)。

目标是导入多个 `.ovpn` 并将其引用的证书材料转换为应用可独立使用的配置副本。导入成功后，原文件被移动或删除不影响连接；证书更新需要重新导入。

## 首版支持范围

| 输入                                              | 首版处理                                     |
| ------------------------------------------------- | -------------------------------------------- |
| 已内嵌证书的 `.ovpn`                              | 校验后保存                                   |
| `ca` 外部 PEM 证书或证书链                        | 读取并转换为内嵌 CA                          |
| `cert` 外部 PEM 客户端证书                        | 读取并内嵌                                   |
| `key` 外部未加密 PEM 私钥                         | 读取并内嵌，按敏感数据保存                   |
| 已内嵌的 tls-auth / tls-crypt / tls-crypt-v2 材料 | 按锁定引擎支持情况验证，保留方向等语义       |
| 外部 tls-auth / tls-crypt / tls-crypt-v2 材料     | 选择文件后转换为 inline，保留方向或模式      |
| PKCS#12、硬件令牌、MFA                            | PKCS#12 转换为 inline；硬件令牌和 MFA 仍拒绝 |
| `auth-user-pass` 无文件参数                       | 使用客户端账号密码输入                       |
| `auth-user-pass passwords.txt`                    | 选择凭据文件并转换为 inline                  |

外部材料和仅证书认证必须通过第三步的引擎验证才能交付。不得把文件导入成功等同于任意 OpenVPN 配置均可连接；脚本、插件、配置包含等 OpenVPN Connect 不支持或会产生特权文件访问的指令仍需拒绝。

## 导入流程

1. 原生端检查编译能力，打开系统文件选择器并限制为 `.ovpn`；扩展名仅用于筛选，仍须检查内容。
2. 读取配置，按 OpenVPN 官方规则解析指令、注释、引号、转义、多个 `remote`、`<connection>` 与 inline 块，收集依赖和服务器候选信息。普通客户端指令由随包 OpenVPN 3 引擎校验。
3. 外部材料不按配置路径自动读取；每一项都由用户通过原生文件选择器明确选择。这样既支持相对路径、绝对路径、中文路径和空格路径，也不会让高权限监督进程访问配置指定的任意文件。
4. 缺失材料时展示用途与原引用，例如「请选择 CA 证书 ca.crt」，允许选择对应文件或取消；不猜测同名文件。
5. 将所需材料内嵌，移除对应外部引用，重新校验规范化结果。保留原有 remote、协议、路由及证书校验选项的语义。
6. 显示名称、服务器地址和认证类型供确认；默认名称来自 `.ovpn` 文件名，可修改，作为纯文本显示。
7. 在私有临时目录写入配置和元数据，完成后原子发布目录。失败、取消或磁盘写入错误不留下可选的半成品。
8. 连接空闲时可选中新配置；已有会话时只添加，不切换当前连接或当前选择。

重复内容按规范化内容指纹提示已导入，不覆盖已有条目。相同文件名但内容不同允许导入，显示名称可调整，ID 必须不同。建议初始限制：单个 `.ovpn` 2 MiB、单份证书材料 1 MiB、规范化结果 8 MiB、最多 100 个导入配置；集中定义常量并针对真实样本调整。

## 原生接口设计

接口名称为建议，与现有 `window.vpn` 风格保持一致：

| 接口                         | 作用                               |
| ---------------------------- | ---------------------------------- |
| `vpn_get_capabilities`       | 返回编译能力                       |
| `vpn_list_profiles`          | 返回可用元数据与当前选择           |
| `vpn_begin_profile_import`   | 原生选择文件并创建短期导入草稿     |
| `vpn_resolve_profile_import` | 为草稿中指定依赖打开原生文件选择器 |
| `vpn_commit_profile_import`  | 再校验后保存，返回新增元数据       |
| `vpn_cancel_profile_import`  | 释放草稿和敏感临时数据             |
| `vpn_select_profile`         | 空闲时变更选择并持久化             |
| `vpn_rename_profile`         | 修改导入配置显示名称               |
| `vpn_delete_profile`         | 删除导入配置及对应凭据             |

草稿令牌由后端生成，限定当前应用会话并设置超时。前端传依赖标识，不提供任意文件读取路径。UI 只接收缺失材料说明，不接收私钥正文。新增文件选择器依赖及 Tauri 权限时仅开放所需能力。

## 内容校验与权限边界

当前 `worker.rs` 的安全前提是只使用编译内置配置。动态导入后，应建立版本化的配置策略，并在导入与连接时复用：

- 对客户端需要的指令分类，明确支持、拒绝和需验证的选项；未知或不支持的选项给出指令名和行号，不静默丢弃。
- 拒绝脚本、插件、配置包含、任意输出路径和未解析文件引用等超出客户端能力的指令。具体清单必须依据仓库锁定引擎源码与运行验证形成，不能假设 OpenVPN 2 的行为与该引擎一致。
- 仅检查 PEM 标记不足以验证证书。验证证书/私钥可解析性、材料类型，并在适用时检查证书与私钥匹配；证书过期信息明确提示，连接时仍由引擎执行信任链和服务端身份验证。
- 不绕过证书验证，不自动删除用户配置中的服务端身份限制，也不为“兼容”改写网络目标。
- 规范化副本不能保留需要特权进程读取的用户外部路径。连接时监督进程仍需重新校验实际收到的配置字节。

POSIX 下敏感目录权限为 0700、文件为 0600；Windows 使用当前用户受限 ACL，并兼容必要的 SYSTEM/管理员访问，不假定临时文件库自动满足全部隔离要求。不得在日志、错误详情或前端状态中输出私钥、密码、完整配置正文。

## 持久化和删除

新增 `profile_import.rs` 负责解析、依赖解析及规范化，`profiles.rs` 负责存储与元数据，不让 UI 管理文件。可通过独立解析模块让普通进程与监督进程共用策略。

导入目录以原子重命名发布；全局选择状态通过临时文件替换写入。启动时清理过期导入草稿，检测并报告损坏条目。执行写操作前串行化配置变更，避免删除与连接同时发生。

当前活动配置在连接中、取消中、已连接或断开清理阶段禁止删除。删除操作先将配置标记为不可用，再清理凭据和文件；失败保留可重试记录，不能显示“已全部删除”。卸载时覆盖所有导入配置、草稿及每配置凭据条目，保留现有卸载路径边界检查。

## 本步骤验收

- 内嵌配置、外部 CA、外部 cert/key、空格路径、中文路径、CRLF、带引号路径、注释和多 remote 均有样本验证。
- 缺失 CA 可补选；取消、重复导入、无效 PEM、超限、磁盘失败不会污染现有配置。
- 导入后删除原始文件仍可加载规范化副本；原始文件未被改写。
- 跨目录引用需明确选择；路径穿越、链接替换、网络路径、脚本及未解析引用被正确处理。
- 关闭导入时直接调用导入接口也失败；不能通过篡改草稿 ID 或配置 ID读取任意文件。
- 文件权限、崩溃恢复、损坏条目隔离和删除失败重试在 Windows/macOS 分别验证。
